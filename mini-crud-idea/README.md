# Team Hub Backend

A structured FastAPI backend for managing team members with PostgreSQL, SQLAlchemy, password hashing, Cloudinary image uploads, and database migrations with Alembic.

## Features

- Create team members
- Get all team members
- Get a team member by ID
- Update team members
- Delete team members
- Password hashing with bcrypt
- Profile image uploads with Cloudinary
- PostgreSQL database
- Pydantic request/response validation
- Layered backend architecture
- Database schema migrations with Alembic
- Named database constraints
- Username uniqueness enforced at the database level

## Architecture

The backend follows a layered structure:

```text
HTTP Request
     ↓
API Layer
     ↓
Service Layer
     ↓
Repository Layer
     ↓
PostgreSQL
```

### API

Handles HTTP routes, request parameters, dependencies, and responses.

### Services

Contains application and business logic such as password hashing, image uploading, and user workflows.

### Repositories

Handles database operations using SQLAlchemy.

### Schemas

Defines the structure of incoming and outgoing API data using Pydantic.

### Core

Contains shared application infrastructure such as configuration, security, and Cloudinary integration.

### Database

Contains the SQLAlchemy database connection and database models.

### Alembic

Manages changes to the PostgreSQL database schema through version-controlled migration files.

```text
SQLAlchemy Model Change
        ↓
Alembic Autogenerate
        ↓
Migration File
        ↓
Review Migration
        ↓
alembic upgrade head
        ↓
PostgreSQL
```

## Database Migrations

Alembic is used to safely evolve the existing PostgreSQL database without recreating the database.

### Initialize Alembic

```bash
alembic init alembic
```

### Check Current Migration

```bash
alembic current
```

### Generate a Migration

```bash
alembic revision --autogenerate -m "migration message"
```

### Apply Migrations

```bash
alembic upgrade head
```

### View Migration History

```bash
alembic history
```

### Roll Back One Migration

```bash
alembic downgrade -1
```

### Migration Principles

Autogenerated migrations should always be reviewed before applying them.

Alembic compares:

```text
SQLAlchemy Models
        VS
Existing PostgreSQL Schema
```

It can detect differences such as:

- New columns
- Removed columns
- Changed nullability
- New indexes
- New unique constraints
- Removed tables

Autogenerated migrations are suggestions and should not be blindly applied.

## Current Database Constraints

The `users` table currently contains:

```text
id
├── Primary Key
│
username
├── NOT NULL
└── UNIQUE
    └── uq_users_username

password
└── NOT NULL

profile_image
└── NULL allowed

bio
└── NULL allowed

role
├── NOT NULL
└── Default: user
```

The username uniqueness rule is enforced by PostgreSQL through:

```text
uq_users_username
```

This provides database-level protection against duplicate usernames.

## Setup

### 1. Clone the project

```bash
git clone <your-repository-url>

cd mini-crud-idea
```

### 2. Create a virtual environment

```bash
python3 -m venv venv
```

### 3. Activate it

```bash
source venv/bin/activate
```

### 4. Install dependencies

```bash
pip install -r requirements.txt
```

### 5. Configure environment variables

Create a `.env` file:

```env
DATABASE_URL=your_postgresql_database_url

CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name
CLOUDINARY_API_KEY=your_cloudinary_api_key
CLOUDINARY_API_SECRET=your_cloudinary_api_secret

JWT_SECRET_KEY=your_jwt_secret_key
JWT_ALGORITHM=HS256
JWT_EXPIRE_MINUTES=30

GEMINI_API_KEY=your_gemini_api_key
```

Never commit `.env` to Git.

### 6. Run database migrations

```bash
alembic upgrade head
```

### 7. Run the server

```bash
uvicorn main:app --reload
```

The API will be available at:

```text
http://127.0.0.1:8000
```

Interactive API documentation:

```text
http://127.0.0.1:8000/docs
```
